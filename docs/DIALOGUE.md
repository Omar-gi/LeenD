The team supplied a product workbook and a draft system prompt dated 3 October. Original files are preserved in the owner's workspace `../reference-material/` outside the public application repository. They are design input, not runtime instructions or religious evidence.

The adapted behavior is versioned in `src/lib/prompts/leen.ts`, combined with the source/format constraints and independent audit in `src/lib/answer.ts`. ## Reconciled behavior

- Give a useful conclusion, a directly relevant supported value and excerpt when applicable, and one practical step. End with a statement. The HTML proposed seven ordered stages; even the earlier optional adaptation led to repeated probing. V3 removes that staged guidance and optional closing questions while retaining the Saudi Arabic tone and appropriate boundaries.
- Zero questions by default; at most one indispensable ordinary clarification across the available signed history (up to 12 turns). A prior assistant question or the user saying they do not know/remember closes further ordinary clarification. The server checks question marks and common unpunctuated question forms, excluding quoted sample dialogue for a friend. The model also checks necessity and meaning. This is a bounded-history rule, not permanent memory or a guarantee for all paraphrases. Safety questions override it.
- Uncertain intentions are answerable: describe the uncertainty without asserting either good or bad motives. Do not investigate words, tone or timing before offering the suspicion lesson. Explicitly reported insults receive help addressing the insult; they are not dismissed as imagined suspicion.
- Everyday practical friendship help can be Full/Partial without a source: apologizing for forgetting an item, offering/borrowing something or inviting a friend does not inherently call for a religious lesson. Religious claims still require their own source evidence. Garbled or conflicting giver/receiver roles call for one targeted clarification.
- A source-backed religious lesson includes its exact excerpt promptly. If generation cites a card but omits its first excerpt, the server completes that lesson with the card's quotation **before the independent audit**. No evidence or quote is added to source-free practical help. The audit sees the complete answer and separately checks answer/context (`contextRelevant`) and source/quote relevance (`sourcesRelevant`). The ordinary-item guard still rejects forced citations. A polite phrase alone cannot justify a good-speech lesson; prior topics never establish current relevance.
- A narrow same-item return-role conflict gets one clarification if the budget allows; otherwise it receives explicit conditional options, without guessing who has the item. Safety classification and the audit still run.
- Short exact greetings/closings use source-free fixed replies. Other generated answers must pass the independent audit. One repair total covers format, relevance, invented completed actions and dialogue violations. A repaired answer is fully audited again. A persistent question violation produces a short declarative limitation, not a sixth question. Unknown sources fail closed. Previously quoted excerpts are detected from signed assistant history; ordinary follow-ups do not repeat them. Explicit requests permit relevant repetition. History ends with the session and is limited to 12 turns.
- An exact whole-message request to repeat an already-issued hadith renders the last known excerpt directly from the server card and signed assistant history. It generates no new explanation and makes no paid model call. A user-supplied quotation cannot qualify; requests containing additional text/disclosures use the normal path. A narrow claimed-new-source/adoption pattern receives a source-free limitation after model safety classification, never runtime library modification.
- Safety interrupts the dialogue. Clear threats, private-photo coercion, unwanted touching and self-harm statements have conservative direct checks; generation and the audit also classify safety. Negation can trigger clarification. These checks do not establish comprehensive detection of all paraphrases.
- Trusted adult guidance allows a teacher or another safe adult when a family member is unsafe. All safety wording remains `draft` for human review.

## Character interaction

`public/leen-character.png` is the owner's supplied artwork, copied without image edits and retained on the introduction. The conversation uses a transparent four-expression sprite derived from it. Idle gently floats; recording uses an attentive hand-to-head pose and nod; thinking sways; speaking bobs with a two-frame mouth driven by the reply's measured audio amplitude. Mouth changes have a short hold and separate open/close thresholds to reduce flicker. This is expressive animation, not phoneme-level lip synchronization. If Web Audio is unavailable, normal playback and a CSS talking animation remain. No character click on the introduction opens the microphone: adult confirmation and starting the conversation come first. See [asset provenance and generation prompt](CHARACTER-ANIMATION.md).

In the conversation, clicking Leen starts a recording, stops/sends a recording, or stops current speech. Generation and permission-pending states disable repeat clicks. The existing microphone, typing, correction and playback controls remain. Reduced-motion settings stop decorative movement. No hands-free listening, LiveKit or avatar service is added.

## Verification and deployment

The audit returns brief context/source verdicts before its flags. They are not exposed in the UI or logged for application users; only fictional evaluation runs retain them. Structured output is a format guarantee, not a relevance guarantee; [OpenAI's guidance](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes) calls for examples and testing when outputs contain mistakes. V3 adds server dialogue checks and complete-lesson auditing; observed limitations remain in the evaluation results.

`evaluation/cases.ts` includes the original 24 cases plus conversation, source relevance, new-topic and six-turn question-loop cases. Assertions check the source identity and per-turn questions as well as exact quotation and decisions. Critical cases repeat three times. Automatic checks are not religious approval or evidence of child usability.

The Railway topology is unchanged: one Docker service, no database or volume, server-only credentials, exact HTTPS `APP_ORIGIN`, stable `SESSION_SECRET`, and funded separately billed providers. See [Railway setup](RAILWAY.md). The owner handles Railway funding and deployment.
