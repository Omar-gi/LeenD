The team supplied a product workbook and a draft system prompt dated 3 October. Original files are preserved in the owner's workspace `../reference-material/` outside the public application repository. They are design input, not runtime instructions or religious evidence.

The standalone dialogue policy is versioned in `src/lib/prompts/leen.ts`, combined with the source/format constraints and independent audit in `src/lib/answer.ts`. ## Reconciled behavior

- `src/content/scope.json` contains the 15 domain labels/descriptions from the team's 5 October scope CSV, E4:F18. It is a topic boundary, **not** Sara's detailed knowledge table or religious evidence. A separate first model call classifies the current need and selects eligible source IDs before answer generation. The independent auditor also classifies the current need as friendship, social, simplify, outside, mixed, clarify or safety, and identifies at most two scope categories. The classifier receives a small source catalog; only selected full source cards reach the writer and verifier. A server allowlist rejects unselected evidence, with at most one shared repair. This is semantic selection over local JSON, with no vector database and no newly imported religious corpus.
- Short greetings return conventional Arabic (including وعليكم السلام), and everyday how-are-you/thanks/closings get brief fixed social responses. Whole-message matching prevents a greeting from swallowing another need or disclosure. These paths skip answer generation; optional speech synthesis is still a paid call.
- Requests to simplify get a short concrete explanation of the previous point. They cannot introduce a new quotation; any attached evidence must already appear in the earlier authenticated assistant excerpt in the bounded session. A deterministic hint also enforces this on common Arabic wording. For a request classified as simplification of an already cited and currently selected meaning (or the immediately preceding exact excerpt), the server returns its authored simple variant after the classifier checks scope and safety; ordinary source-free simplification is generated and audited. A simplification phrase inside a new or mixed request cannot bypass generation/auditing or its required scope limit. The semantic audit handles other paraphrases. The prior answer is not evidence of correctness; it may need correction. No-history confusion cannot invent a prior story.
- Anger, dislike, needing space and considering ending a friendship are in scope. Offer ordinary support and a safe practical option, without requiring a source, forced forgiveness, a forced permanent decision or imagined motives. The audit rejects generic missing-evidence referrals that fail to meet this ordinary need.
- Unrelated technical topics, adult topics and homework stay outside scope even when a friend is mentioned. A router or auditor classification of outside returns a short fixed boundary; safety is checked first. For mixed requests, the classifier extracts an exact substring for the friendship need. The server checks it is actually in the input, sends only that part to the writer, and appends a fixed limitation before auditing against the full request. A bad extraction fails closed. Previous session context remains available and still needs semantic checking. Classification remains model-dependent, not a perfect topic filter.

- Give a useful conclusion, a directly relevant supported value and excerpt when applicable, and one practical step. End with a statement. The HTML proposed seven ordered stages; even the earlier optional adaptation led to repeated probing. V4 replaces the dialogue policy with current-need rules, keeps Saudi Arabic and boundaries, and removes the long example dialogues from generation to reduce example-detail leakage.
- Zero questions by default; at most one indispensable ordinary clarification across the available signed history (up to 12 turns). A prior assistant question or the user saying they do not know/remember closes further ordinary clarification. The server checks question marks and common unpunctuated question forms, excluding quoted sample dialogue for a friend. The model also checks necessity and meaning. This is a bounded-history rule, not permanent memory or a guarantee for all paraphrases. Safety questions override it.
- Uncertain intentions are answerable: describe the uncertainty without asserting either good or bad motives. Do not investigate words, tone or timing before offering the suspicion lesson. Explicitly reported insults receive help addressing the insult; they are not dismissed as imagined suspicion.
- Everyday practical friendship help can be Full/Partial without a source: apologizing for forgetting an item, offering/borrowing something or inviting a friend does not inherently call for a religious lesson. Religious claims still require their own source evidence. Garbled or conflicting giver/receiver roles call for one targeted clarification.
- The provider response schema permits religious text only as empty meaning/quote placeholders referencing the selected cards. With no selected sources those placeholder kinds are absent entirely. Source-backed explanations are rendered from the card's authored `childExplanation` (or `simpleExplanation` on simplification), not freely rewritten by the model. These new short meanings are drafts based on the existing permitted explanations, awaiting the same human review. Practical application stays separate and is generated, then audited. This prevents the observed embellishments inside source-backed meaning segments; it does not prove source-free text can never contain a missed unsupported claim.
- A source-backed religious lesson includes its exact excerpt promptly. If generation cites a card but omits its first excerpt, the server completes that lesson with the card's quotation **before the independent audit**, except during simplification. The separately selected first lesson can complete a writer's practical-only draft with the matching fixed meaning and excerpt before audit. No lesson is selected for ordinary practical help. The audit sees the complete answer and separately checks answer/context (`contextRelevant`) and source/quote relevance (`sourcesRelevant`). The ordinary-item guard still rejects forced citations. A polite phrase alone cannot justify a good-speech lesson; prior topics never establish current relevance.
- A narrow same-item return-role conflict gets one clarification if the budget allows; otherwise it receives explicit conditional options, without guessing who has the item. Safety classification and the audit still run.
- Short exact greetings/closings use source-free fixed replies. Other generated answers must pass the independent audit. One repair total covers format, relevance, invented completed actions and dialogue violations. A repaired answer is fully audited again. A persistent question violation produces a short declarative limitation, not a sixth question. Unknown sources fail closed. Previously quoted excerpts are detected from signed assistant history; ordinary follow-ups do not repeat them. Explicit requests permit relevant repetition. History ends with the session and is limited to 12 turns.
- Exact whole-message requests for a named existing excerpt can also look up that stored text directly, with no invented claim or model routing. Contextual requests for an available excerpt use the classifier-selected stored meaning/quotation and an independent relevance audit, avoiding freeform scripture regeneration.
- An exact whole-message request to repeat an already-issued hadith renders the last known excerpt directly from the server card and signed assistant history. It generates no new explanation and makes no paid model call. A user-supplied quotation cannot qualify; requests containing additional text/disclosures use the normal path. A narrow claimed-new-source/adoption pattern receives a source-free limitation after model safety classification, never runtime library modification.
- Safety interrupts the dialogue. Clear threats, private-photo coercion, unwanted touching and self-harm statements have conservative direct checks; generation and the audit also classify safety. Negation can trigger clarification. These checks do not establish comprehensive detection of all paraphrases.
- Trusted adult guidance allows a teacher or another safe adult when a family member is unsafe. All safety wording remains `draft` for human review.

## Character interaction

`public/leen-character.png` is the owner's supplied artwork, copied without image edits and retained on the introduction. The conversation uses a transparent four-expression sprite derived from it. Idle gently floats; recording uses an attentive hand-to-head pose and nod; thinking sways; speaking bobs with a two-frame mouth driven by the reply's measured audio amplitude. Mouth changes have a short hold and separate open/close thresholds to reduce flicker. This is expressive animation, not phoneme-level lip synchronization. If Web Audio is unavailable, normal playback and a CSS talking animation remain. No character click on the introduction opens the microphone: adult confirmation and starting the conversation come first. See [asset provenance and generation prompt](CHARACTER-ANIMATION.md).

In the conversation, clicking Leen starts a recording, stops/sends a recording, or stops current speech. Generation and permission-pending states disable repeat clicks. The existing microphone, typing, correction and playback controls remain. Reduced-motion settings stop decorative movement. No hands-free listening, LiveKit or avatar service is added.

## Verification and deployment

The audit returns brief context/source verdicts before its flags. They are not exposed in the UI or logged for application users; only fictional evaluation runs retain them, along with the route and selected source IDs. Structured output is a format guarantee, not a relevance guarantee; [OpenAI's guidance](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes) calls for examples and testing when outputs contain mistakes. V4 additionally enforces response-mode limits and makes scope classification visible in fictional evaluation reports; observed limitations remain in the evaluation results.

`evaluation/cases.ts` includes the original 24 cases plus conversation, source relevance, new-topic and six-turn question-loop cases. Assertions check the source identity and per-turn questions as well as exact quotation and decisions. Critical cases repeat three times. Automatic checks are not religious approval or evidence of child usability.

The Railway topology is unchanged: one Docker service, no database or volume, server-only credentials, exact HTTPS `APP_ORIGIN`, stable `SESSION_SECRET`, and funded separately billed providers. See [Railway setup](RAILWAY.md). The owner handles Railway funding and deployment.
